## MCP Server实战

从这里，我们就不难看出，MCP Server是大模型与外部世界“无缝对接”的桥梁，尤其在企业级场景下，能让大模型轻松触达组织内部的“宝藏”。MCP Server提供了三种能力分别是Tools（工具）、Resources（资源） 和 Prompts（提示词），那我就详细说说这三个“超能力”。
![](https://static001.geekbang.org/resource/image/18/64/185yya78e978300a8a1b931cbcff0064.png?wh=2280x1040)

### Tools：大模型的“超级助手”

Tools就是给大模型准备的功能按钮，和我们手机里查天气、发邮件等工具一样，能够让大模型连接外部的世界，每个Tool都有个名字、描述和输入规则，输出按照约定要求返回。大模型不是乱按按钮的，它会根据你的问题选择用哪个 Tool。大模型本来只是个“脑力型选手”，不会上网或操作软件。Tools 让它变“全能战士”——比如你问“今天北京天气咋样？”，AI 就会调用 Tools 去查实时数据，而不是胡编乱造。下面是一个非常简单的Tool的例子，为大模型提供了加法计算的工具。

```perl
from mcp.server import FastMCP # 导入 FastMCP 库（MCP 的快速开发工具）
mcp = FastMCP("Demo")# 这个Demo就是MCP Server的名字
@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers"""
    return a+b

if __name__ == "__main__":
    # Initialize and run the server
    mcp.run(transport='stdio')
```
完成开发后，进入MCP Host进行配置后就可以使用了，下面是一个配置的举例，其他类似。

### Resources：大模型的“知识库”

Resources 就像Server里面的文件柜，存着各种数据，例如各种相关文本文件、数据库Schema、Git仓库等，它让AI随时可以翻阅数据，而无需每次都从零开始聊天。Resources不是静态的存储数据，而是 MCP Server 的活知识库，能动态注入到大模型的记忆中，让它像老员工一样懂你的项目细节，下面是一个将本地文件作为Resource返回的MCP Server。

```perl
from mcp.server import FastMCP # 导入 FastMCP 库（MCP 的快速开发工具）

mcp = FastMCP("Demo")# 这个Demo就是MCP Server的名字

@mcp.resource(  # 装饰器：注册一个静态资源（固定 URI，不带参数）
    uri="file:///project/README.md",  # 资源的"地址"：本地文件路径，file:/// 是标准协议
    title="项目 README",  # 标题：人话描述，AI list 时显示
    description="功能概述",  # 描述：告诉 AI 这个资源是干啥的（电商项目概述）
    mime_type="text/markdown"  # 文件类型：Markdown 文本，AI 知道怎么解析（e.g., 渲染成 HTML）
)

def get_readme():# 绑定的函数：Server 收到 read 请求时执行这个
    with open("project/README.md", "r", encoding="utf-8") as f:  # 打开本地文件，指定UTF-8编码
        return f.read()  # 返回文件内容（纯文本），Server 自动包成 MCP 响应


if __name__ == "__main__":
    # Initialize and run the server
    mcp.run(transport='stdio')
```
### Prompts：大模型的“导演脚本”

这里的Prompt是server预设好的内容，每个 Prompt 像一部剧本：有标题、情节描述。核心是让大模型的输入（prompt）标准化——不是你每次从头编长篇大论，而是 Server 一键生成完美开局，大模型收到后直接入戏。下面就是一个MCP的Prompt的例子，预设了一个专业设计测试用例的剧本。

```perl
from mcp.server import FastMCP  # 导入 FastMCP 库（MCP 的快速开发工具）
mcp = FastMCP("Demo")  # 创建 MCP Server 实例，名字 "Demo"
@mcp.prompt(  # 装饰器：注册 Prompt
    name="testcase_gen",  # 内部 ID（小写 + 下划线规范）
    title="边界值测试用例生成器",  # 新增：UI 短标题
    description="根据输入的需求描述，采用边界值分析法设计测试用例（覆盖正常/边界/异常输入）"  # 优化描述：更精确
)
def testcase_gen(message: str) -> list:  # 改返回：list of dicts（消息列表）
    return [  # 标准 messages 结构：system + user
        {  # System 消息：设角色 + 规则（隐形导演）
            "role": "system",
            "content": """你是资深测试开发工程师，专精边界值分析法。
边界值原则：针对输入范围，测试 min、max、min-1、max+1、nominal（正常值）、空值/无效。
输出格式：用 Markdown 表格列出用例（ID | 输入 | 预期 | 类型：正常/边界/异常）。
保持简洁、专业，只输出用例表，无多余解释。"""
        },
        {  # User 消息：注入需求 + 引导
            "role": "user",
            "content": f"需求：{message}\n\n请基于边界值方法设计测试用例。"
        }
    ]
if __name__ == "__main__":
    # Initialize and run the server
    mcp.run(transport='stdio')
```
## MCP inspector是MCP的调试器

说完了MCP Server的开发，就不能不聊聊MCP inspector这个测试和调试MCP Server的交互工具。简单说，MCP就像大模型外接的USB接口，而MCP Inspector就是检测这个接口的测试仪，帮你检查接口通不通、数据对不对，避免上线时出大乱子。


MCP inspector是MCP官方提供的开源工具，本质上就是一个基于浏览器的交互UI，它由两部分组成，一部分是MCP Inspector Client的前端，默认端口是6274，可以通过这个Client端给MCP Server发请求、看响应等；另外一部分是MCP Proxy Server，是后端服务的代理，默认端口是6277，桥接本地 MCP Server 和 Inspector，确保数据实时流通。


MCP Inspector是js开发的代码，通过npm install安装，通过命令启动服务后，就可以在本地的6274端口完成访问了。

## MCP 的本质与 Python 实现的“聪明设计”详解

MCP 就是一个给 LLM 快速调用外部的 tool、resource、Prompt 的一个手段，那么在写 MCP Server 的时候，充分利用了 Python 的 Docstrings 和 Type Hints，让 LLM 更好地理解工具以及工具的参数，LLM 就可以知道什么时候应该通过 MCP 调用解决问题了。


MCP 不是什么复杂的框架，而是专为大语言模型（LLM，如 GPT 或 Claude）设计的标准化协议，让 LLM 能“无缝触达”外部世界。它本质上就是一个快速通道：

* **Tool**：让 LLM 调用外部函数，不限于聊天。

* **Resource**：提供数据“知识库”，LLM 可随时拉取背景。

* **Prompt**：预设“剧本模板”，引导 LLM 输出更结构化、专业。


为什么说它是一个“快速通道”呢？MCP 用 JSON-RPC 协议轻量，通过 Host和 Server中转，延迟毫秒级。LLM 收到任务时，会“自省”这些能力，决定用哪个解决问题，MCP 就是 LLM 的外部扩展包。Anthropic设计Python开发MCP server包FastMCP的时候，充分利用了Python的两大特性，Docstring和Type Hints，这才能让开发MCP Server的过程和开发普通函数的过程一样。

* Docstring就是函数的三个引号的注释，这个注释就是让大模型理解工具的描述字段，因此我们要做到见文知意，不要写得云里雾里的，避免歧义。

* Type Hints是Python3.5以后的版本中引入的，`def add(a: int, b: int) -> int` 这样标注类型的方法，MCP用它生成参数 schema，精确定义类型。


大模型在调用MCPServer的时候是先解析用户的意图，再匹配Tool/Resource/Prompt的描述和参数。如果Docstrings写得清晰，Type Hints精确，大模型选择的就会更准确，例如用户问“如何设计登录测试用例”？匹配到 Prompt 的 description，它优先调用，而不是纯文本生成。 这是基于大模型的提示词工程的，MCP Host 会把这些元数据注入到系统提示中，让 LLM 知道调用的边界。

## MCP Client

最后我们来讲讲MCP Client，MCP Client是在MCP Host里面，提供访问MCP Server的客户端。当前我们常用的例如Claude Desktop、Cursor、VSCode的Cline插件等等都是非常好的MCP Host，里面都集成好了MCP Client。我在课程对应的 [Github仓库](https://github.com/crisschan/LLM4Test)中提供了一个简单的MCP Client代码，如果你感兴趣就打开看一看，在实际工作中，测试开发工程师很少需要自行开发MCP Client，我们只要选择一个得心应手的MCP Host就可以了。
